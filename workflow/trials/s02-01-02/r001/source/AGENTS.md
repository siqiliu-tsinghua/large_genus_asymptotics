# 项目协作约定

本项目证明 Introduction 中的四个纯 Hodge 积分大亏格渐近定理。论文正文使用英文，研究计划、交接和审核记录可以使用中文。先读 paper_outline.md 和 workflow/context.md，再读自己的角色文档及目标 section 对应的提纲。

## 文件与所有权

- 每个 section 使用 sections/ 中的独立目录；section.tex 是章节入口和证明导读，每个 subsection 使用单独的 .tex 文件。
- main.tex 负责装配；tex/preamble.tex 管理共享宏；references.bib 管理正式引文。
- sections/included.tex 由脚本生成，只装配正文中连续验收通过的章节。既有 Introduction 是保留的基线，不代表已经通过新流程审核。
- 每个章节的 INTERFACE.md 记录导出记号、命题、标签、假设、文献及待解决问题，随正文一起审核。
- 作者只修改所分配的 section 目录，以及协调者指定的本轮作者答复和交接文件。共享文件的修改向协调者提出，由协调者统一处理。
- 审核者不直接改论文；只写自己的审核报告和交接文件，不修改其他审核者的意见。
- refs/ 是本机参考资料，build/ 是生成目录；二者不加入 Git。所有受版本管理的文本使用 UTF-8、LF 和文件末尾换行。

## 工作单元与会话

- 以一个 section 为完整验收单元，内部按 subsection 起草。一次只推进一个未验收单元，完成写作、审核、返工、复审和验收后再开下一节。
- 每节固定一个 writer、一个 math 审核者、一个 readability 审核者和一个 academic 审核者。职责见 workflow/roles/。
- 新角色首次调用 collaboration.spawn_agent，使用 fork_turns="none"，按脚本生成的提示词读取目标上下文；立即把返回的真实 agent ID 绑定到该角色。
- 返工使用 collaboration.followup_task 发给原 writer；复审同样发给原审核 agent。禁止为每一轮重新 spawn 或交换 reviewer ID。
- 同一角色可以跨轮、跨节复用；跨节复用时先 bind 原 ID 到相同角色，再 dispatch。不能兼任作者与审核者，也不能由同一个 agent 冒充不同审核角色。
- 并发受工具实际额度约束。当前上限包括协调者在内为四个运行中的 agent：作者提交后保持会话可复用，三类审核可以并行；额度不足时分批审核，仍复用原 ID。
- 只为当前 section 激活角色；新角色不继承整段研究历史。首次提供角色、目标、提纲位置和必要接口；后续只发送新快照、差异、意见和答复。
- 原会话必须保留以便返工和复审。若会话确实不可恢复，应说明情况并记录交接，不能把新 agent 称为原作者或原审核者。

## 逐轮协议

1. 协调者通过 scripts/workflow.py start 选定工作单元，检查前置依赖。
2. 通过 dispatch 获取真实工具调用参数，调用工具后 bind 对应的真实 ID。脚本不直接启动或假装启动 agent。
3. 原作者完成正文、章节接口和交接。协调者运行单节构建和静态检查，再 submit 冻结一份快照。
4. 三类审核针对同一个冻结快照各自出具报告，协调者逐份 record-review。审核期间正文冻结，禁止作者边改边审。
5. 任一审核要求修改，先收齐本轮全部报告，再由 revise 将工作交回原作者。作者逐条回应 issue ID，返工后提交新一轮。
6. 新一轮由原三位审核者复审。已通过的审核者可以重点检查差异及其影响，但仍须签署新快照；旧版本的 pass 不自动沿用。
7. 三类审核都对同一新快照 pass，构建和检查通过后，由协调者 accept。脚本保存构建收据、审核报告摘要和内容指纹。

不要手工修改 workflow/state.json，不要绕过失败的审核。只有协调者运行会改变工作流状态的命令；subagent 负责产出对应的正文、报告或答复。构建成功不代替数学审核，审核报告也不代替实际构建。

## 数学与写作要求

- 每个数学符号先有定义再使用，包括定理、公式、图表和图注中的符号；说明对象类型、指标范围、固定或变化的参数及作用域。哑变量须在所在公式或紧邻文字中明确绑定。第 2.2 节统一引入 psi、kappa、Chern 特征。
- 全文沿用引言和 workflow/context.md 的记号：g_2 = 2g-3，Hodge 类下标用 j_1, ..., j_ell，ell 表示该乘积的因子数；保留 z_{0,1}、rho、b 等既有名字。不得另起别名或为迁就笔记换字母。
- 尽量少设符号；只为反复使用、具有独立作用且确实减轻阅读负担的对象设专名。一次性的短表达式直接写出。按数学用途选择字母组，区分 Hodge 下标、标记编号、计数、次数、解析变量和常数，避免同一论证中的重载与视觉混淆。
- 作者在 INTERFACE.md 中记录继承和新增记号、定义位置、作用域及新增符号的必要性；协调者维护共享约定。易读性审核分别检查定义、一致性、符号数量和字母设计；数学审核核对定义、范围和语义，学术规范审核核对文献记号换算。任一未解决的记号问题都须返工。
- 明确有限亏格恒等式、固定参数渐近和可交换求和的一致估计之间的差别。控制全体图或卷积的余项，不能只估计每一个固定项。
- 第一大定理的二阶系数仍需从精确输入补算；旧表的代数相加不是这些输入和各组贡献的证明。
- 每个长证明前给整体路线，按功能拆分引理，明确每一步的假设、输出和后续用途。
- 文献结果署名引用，写明版本、原定理或公式及规范换算。内部笔记是计算线索，不替代原始文献；未核实的引文和证明缺口必须标明。
- 不把尚未证明的候选值、数值外推或形式运算写成已证定理，不使用占位文献伪造出处。
- 通过后禁止悄悄修改已验收章节。任何实质修改都要重新进入该节的写作与原角色审核流程；共享内容或依赖变化会使旧快照失效。

## 常用命令

在仓库根目录运行，工具均使用 Python 标准库：

    python scripts/workflow.py status
    python scripts/workflow.py start s02
    python scripts/workflow.py dispatch s02 writer
    python scripts/build.py --unit s02
    python scripts/validate.py
    python -m unittest discover -s tests -v

完整命令顺序、报告格式、会话复用和异常恢复见 workflow/PROTOCOL.md。此设置阶段不自动开始论文写作。提交使用现有 ~/.gitconfig 中的身份，不在仓库中覆盖姓名和邮箱。
